# Learn GitHub Copilot: A Beginner's Course

Welcome! This course is for **non-technical beginners** who want to learn the basics of GitHub Copilot. You do not need to know how to program. You will learn by asking Copilot questions, trying small examples, and checking the answers.

## What you will learn

By the end of this course, you will be able to:

- explain what GitHub, a repository, and GitHub Copilot are;
- open Copilot in a browser, GitHub Codespaces, or Visual Studio Code;
- write a clear prompt and improve it when the first answer is not useful;
- ask Copilot to explain, summarize, and draft text;
- review Copilot's suggestions safely instead of treating them as facts.

## Before you begin

You need:

- a GitHub account;
- access to GitHub Copilot (a trial or a plan provided by your organization may be available);
- a web browser;
- about 30 minutes and a willingness to experiment.

**No installation is required for the browser lessons.** If you use Codespaces or Visual Studio Code, Copilot may ask you to sign in and authorize access.

## A few words in plain language

| Word | Meaning |
| --- | --- |
| GitHub | A website where people store and work on projects. |
| Repository (repo) | A project folder on GitHub. |
| Prompt | The question or instruction you give Copilot. |
| Chat | A conversation with Copilot about a task. |
| Codespace | A ready-to-use development computer in the cloud. |
| VS Code | An app for working with files and projects. |

## Lesson 1: Meet Copilot

1. Open a Copilot chat in the GitHub website, Codespaces, or VS Code.
2. Try this prompt:

   > Explain GitHub Copilot to me as if I have never written code. Use five short bullet points.

3. Ask a follow-up question:

   > Give me a simple, everyday example of each point.

Notice that you can continue the conversation. Copilot uses the earlier messages to understand the context.

## Lesson 2: Write a useful prompt

A useful prompt usually includes:

1. **The task** — what you want done.
2. **The context** — information Copilot needs.
3. **The format** — how you want the answer presented.
4. **The audience** — who will read or use it.

For example:

> Draft a friendly three-sentence welcome message for people attending their first online class. Use simple language and do not use technical terms.

Try changing the audience or format. Ask Copilot to make the answer shorter, more formal, or easier to understand.

## Lesson 3: Use Copilot as a learning partner

Copilot can help you learn without doing all the work for you. Try:

> Teach me what a variable is. Start with a real-life analogy, then show one tiny example. Ask me one question to check my understanding. Do not assume I know programming.

If you see code that you do not understand, ask:

> Explain this one line at a time. Define every new word and stop after each section so I can ask questions.

It is fine to say, “I do not understand.” Asking for a simpler explanation is part of learning.

## Lesson 4: Practice with a small project

Ask Copilot to help you create a personal checklist:

> Help me make a one-week reading checklist. First ask me what I want to read and how much time I have each day. Then return a table with the day, task, and estimated minutes. Do not create code.

Review the result. Change one detail and ask Copilot to update only the affected row. This demonstrates that Copilot can help with everyday planning, not only programming.

For an optional coding activity, ask:

> Create a tiny web page that says “Hello, Copilot!” Explain where each part goes and how I can view it. Assume I am a complete beginner.

Only copy or run code after you understand what it is intended to do.

## Check your understanding

Answer these questions in your own words:

1. What is a prompt?
2. What three details could make a prompt clearer?
3. Why should you review Copilot's answer?
4. What would you ask Copilot if an explanation were too difficult?

You can ask Copilot to quiz you, but write your answers before requesting help. Learning is more effective when you think first.

## Use Copilot responsibly

Copilot is an assistant, not an authority. Always:

- check important facts with a trusted source;
- read and test code before using it;
- remove private information, passwords, and access tokens from prompts;
- ask for clarification when an answer is vague or surprising;
- credit sources and follow licenses when using generated or quoted material.

Copilot can be confidently wrong, may misunderstand your request, and may produce suggestions that need editing.

## If something goes wrong

- **You cannot find Copilot:** confirm that you are signed in with the GitHub account that has Copilot access.
- **The answer is too technical:** say, “Use everyday language and define each technical word.”
- **The answer is not what you wanted:** describe the goal again, add context, and specify the desired format.
- **A code example fails:** share the exact error message (without private information) and ask Copilot to explain the likely cause before changing anything.

## Continue learning

Repeat the lessons with a topic you care about. Keep a small list of prompts that worked well and improve them over time. The goal is not to accept the first answer—it is to learn how to ask, check, and refine.
